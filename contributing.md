The purpose of these guidelines is to ensure

making changes easier to understand, track, and 
maintain. A well-organized project improves
collaboration, reduces confusion, and helps
prevent unnecessary errors.

## Guidelines

### Commit Message Format
Every commit message must follow this structure:
`[type] Path: description`

### Commit Types
- **PLUS** = New features or functionality
- **BUG** = Bug Fixes
- **MAINTENANCE** = Code maintenance and improvements
    1. Corrective maintenance
    2. Adaptive maintenance
    3. Perfective maintenance
    4. Preventive maintenance
- **DOCS** = Documentation updates
- **REFACTOR** = Code restructing and style improvements without changing intended functionality
- **TEST** = Adding or updating test.

## Final Note
Organization is essential to maintaining a realiable
and sustainable project. By following these guidelines,
We can keep our project history clean and make collaboration
more efficient, and ensure that every change has a clear
purpose.

Good code is important, but it is also organized and maintainable. 
Code is what allows a project to grow.
